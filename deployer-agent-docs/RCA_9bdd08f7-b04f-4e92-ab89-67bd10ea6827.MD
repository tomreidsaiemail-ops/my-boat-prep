# RCA — Route Planning dates (depart_at / event_at / finish_at) disappear in production

App: myboatprep.com (gemini-prototype) · React + FastAPI + Mongo · frontend_type=cloudflare · active run 9bdd08f7-b04f-4e92-ab89-67bd10ea6827

## Reported symptom
On the Route Planning checklist (list id `routeHazards`), the user fills in Departure / Start / Estimated Finish date-times. They save client-side to `boat.weather.depart_at` / `event_at` / `finish_at` and sync via `PUT /api/me/boat`. Switching lists and returning shows all three empty again. Not reproducible in preview.

## What was checked (evidence)

### 1. Are the sync requests failing (4xx/5xx, 413, 422, timeout)? → NO.
- 24h of backend logs: **every** `PUT /api/me/boat?boat_id=main` and `GET /api/me/boat?boat_id=main` returns **200 OK**. No 413, no 422, no 5xx, no timeouts on the sync path.
- Targeted scan for `Traceback|Exception|ValidationError|500|RequestValidationError|422` over 24h returned **zero** backend errors on the endpoint. The only "errors" in logs are `GET /health 404` (nginx probe hits a path the backend doesn't define — harmless) and a few nginx `connect() refused`/`upstream timed out` lines on `/health` during pod restarts. Transport is NOT the cause.

### 2. What does the stored boat document contain?
`user_boats`, `owner_id=user_653ce86d246e`, `boat_id="main"`:
- `boat.weather` = `{ advice, advice_at:"6 Nov 2026 at 4:36 PM", event_name:"Sounds Trip - Mock Up Only", meetup, why }`
- **`depart_at`, `event_at`, `finish_at` are ABSENT.**
- `sec_ts.boat` = `2026-11-12T03:10:18.325Z`, equal to `updated_at` → the **most recent** sync wrote this dateless weather object while bumping the boat-section timestamp.
(The user also has a second, empty doc `boat_id="bmveh6ao5"` with `boat={}`; the app uses `main`.)

### 3. Is the production frontend build stale? → NO.
- Fetched the live bundle `https://gemini-prototype.emergent.host/static/js/main.3f154801.js` (with a browser UA; the worker 403s a blank UA). It **contains** `navigator-depart-at`, `navigator-event-at`, `navigator-finish-at`, `navigator-event-name`, `trip-timing`, `depart_at`, `finish_at`. The date-field code IS live in prod.

### 4. Does the backend drop the fields?  → NO.
- `backend/server.py`: `BoatDetails.weather` is `Dict[str, Any]` with only a 24000-byte size validator (`weather_size`). No key whitelist — the server stores whatever `weather` dict the client sends.
- `backend/sync_merge.py` `merge_state`: the `boat` section is merged **wholesale** (`inc.boat` adopted when `inc.sec_ts.boat >= prev.sec_ts.boat`, else `prev.boat`) — last-writer-wins per section, never a key-level drop of specific weather fields.
- Route "advice" is written **client-side** (`NavigatorAsk.jsx` → `onWeather({advice, advice_at})`, merged into current weather), not server-side — so the stored `advice` was written at a moment when local weather already lacked the dates.

### 5. Client write/stamp path
- `BoatPrep.jsx` `patchWeather` → `mutate(s => ({...s, boat:{...s.boat, weather:{...weather, ...patch}}}), {count:false})`. TripTiming's `onChange` for all of depart_at/event_at/finish_at/event_name/meetup is this same `onWeather` → identical handling.
- `defaults.js` `stamp()` sets `sec_ts.boat = now` whenever `prev.boat !== next.boat` (reference); `patchWeather` always makes a new boat object, so weather edits DO bump `sec_ts.boat`. No stamp bug.

## Root cause (client-side state-sync race in frontend/src/hooks/useBoatStore.js)
Local boat state is **replaced by the server's merged copy** on every sync response:
- PUT handler: `if (editsRef.current === edits) setState(serverToState(data))` — adopts the server `boat` verbatim (`serverToState` sets `boat: data.boat`). This is the only overwrite not guarded by `updated_at`.
- Mount / poll / refresh GET: `if (!hadLocal.current || data.updated_at > local.updated_at) setState(serverToState(data))`.

Combined with the server's whole-`boat`-section last-writer-wins merge, a sync round-trip can overwrite the local `weather` with a server copy that predates the just-typed dates; the next boat edit (event_name, why, advice, etc.) then bumps `sec_ts.boat` and durably persists the **dateless** weather. That is exactly the stored state observed: a fresh `sec_ts.boat` carrying `event_name`/`advice` but no dates.

Why prod-only / not in preview: production API calls traverse the Cloudflare worker → k8s backend (much higher round-trip latency), vs preview's direct low-latency backend. The higher latency widens the window between "dates typed locally" and "dates durably stored + echoed back", so the competing load/sync overwrite lands where it never does in the fast preview path. It is a latency-exposed concurrency bug, not an env/secret/build difference.

## Not reproduced live
This needs a real browser session + authenticated user + production latency to trigger. The eph sandbox has the source but no app secrets/auth and cannot drive the React client, so a live repro was not performed. Conclusion is from: 200-only sync logs, the stored dateless document with a fresh `sec_ts.boat`, the verified-current prod JS bundle, and the merge/overwrite code paths above.

## Suggested fix (Code — E1)
Make trip-timing weather fields survive a sync overwrite. Options, in order of preference:
1. Don't blindly adopt the server `boat` on a PUT/GET response when the local boat has unsynced/newer edits — merge per-field (or keep local weather keys whose local edit is newer than the server copy).
2. Give weather trip-timing fields their own field-level timestamps and merge them individually (like list items) instead of replacing the entire `boat` section on one `sec_ts.boat`.
3. At minimum, guard the PUT-response `setState(serverToState(data))` so it does not clobber local `boat.weather.{depart_at,event_at,finish_at}` that are present locally but missing in the echoed server copy.

## Secrets / tier / domain
Not implicated. No secret, tier limit, OOM, or domain/SSL issue involved; this is a frontend data-sync logic defect.
