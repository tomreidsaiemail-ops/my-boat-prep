## ROOT CAUSE (confirmed)
Two independent problems; the synonym defect is the primary one.

### Primary — a catastrophic noise pattern kills ALL synonym matching (Code + bad admin data)
In `frontend/src/lib/mpa.js`, any noise-list label containing regex metacharacters is compiled to a token-filter RegExp (`noiseRules` → `acc.patterns`). The `Admin - Food Noise Words` list contains the entry **`(.*)`** (id 3). `stripNoise()` drops every token for which `patterns.some(re => re.test(token))` is true; `/(.*)/` matches every string (including empty), so **every token of every name is stripped**. `normKey()` therefore returns `""` for all names, `synGroups()` builds nothing, and `wideKeys()`/`subsFor()` produce no keys — synonym and substitution matching silently do nothing.

Reproduced in the sandbox (eph pod) running the real `mpa.js` against the production rule data:
```
=== WITH (.*)    ===  synonym map size: 0 ;  salt -> undefined ;  sea salt -> undefined
=== WITHOUT (.*) ===  synonym map size: 7 ;  salt -> [salt, table salt, sea salt, rock salt, garlic salt]
                                              sea salt -> [salt, table salt, sea salt, rock salt, garlic salt]
```
So removing the `(.*)` entry restores full salt ↔ sea salt ↔ table salt linkage. This is the direct cause of the reported symptom (and it breaks ALL synonyms, not only salt).

### Secondary — the one salt item is in a non-food area (User data)
Even with synonyms fixed, this user's `Salt` would still be ignored by the Provisioning Assistant because its area `Kitchen Left Slide Out Cupboard` is not marked as a food area, and `foodStock()` only scans food-flagged areas. (Also note: no `Sea salt` item exists on the boat.)

---

## FIXES
1. **Code (E1)** — Harden `noiseRules`/`stripNoise` in `frontend/src/lib/mpa.js` so a single admin noise entry cannot wipe all matching: reject/skip noise patterns that match an empty string (e.g. `re.test("")` → true) or that are unanchored catch-alls like `(.*)`/`.*`, and/or anchor patterns to full-token matches. Verified in sandbox that excluding `(.*)` yields a correct synonym map. Requires a redeploy.
2. **User (admin data)** — In the app's admin Template Lists editor, remove the `(.*)` entry from `Admin - Food Noise Words` (list_id `tpl_9bd553a2de`). This is the immediate, no-code workaround that restores synonym matching.
3. **User (boat data)** — For tomreidsemail@gmail.com, mark `Kitchen Left Slide Out Cupboard` as a food area (or move `Salt` into a food-flagged area such as `Kitchen pantry`/`Aft`), otherwise the salt stock is never considered by the Provisioning Assistant.

Nothing was changed; no redeploy performed.
