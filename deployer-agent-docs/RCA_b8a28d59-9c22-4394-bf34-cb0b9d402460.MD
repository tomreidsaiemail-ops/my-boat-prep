# RCA — Crew member cannot join boat "SY Seven CS" via invite link

## Symptom
Crew member `chrissiekmann.cs@googlemail.com` cannot join boat **SY Seven CS** (owner `isabella@lesche.one`) via the emailed `/join/<token>` → `POST /api/crew/join` link.

## Backend logic (backend/crew.py join_crew)
Finds `db.crew_invites` by token_hash → rejects 400 if expired → **rejects 403 if `invite.email != current_user.email.lower()`** → else `$addToSet` crew into `db.user_boats`.

## Evidence from production MongoDB (db: gemini-prototype-test_database)

### (1) Users
- **Crew user**: `user_id=user_d002d8fab337`, email=`chrissiekmann.cs@googlemail.com`, created_at `2026-10-28T08:25:32Z`, password_hash **present**, email_verified=false, no last_boat.
- **Skipper (Isabella)**: `user_id=user_e04feb92d748`, email=`isabella@lesche.one`, created_at `2026-10-28T07:23:32Z`, password_hash present, email_verified=false.
- Note: the crew member's stored address is `@googlemail.com` with local part **`chrissiekmann`** (NO dot between "chris" and "siekmann").

### (2) crew_invites for owner_id=user_e04feb92d748
- One active invite: boat_id=`main`, email=**`chris.siekmann.cs@googlemail.com`**, created_at `2026-10-28T08:14:16Z`, expires_at `2026-11-04T08:14:16Z` (NOT expired), invite_id `97dc2a6a-2b92-4fff-8c69-9c4310632d59`.

### (3) user_boats for owner_id=user_e04feb92d748
- boat_id=`main`, boat.vessel=`SY Seven CS`, crew=`["user_653ce86d246e"]`.
- `user_653ce86d246e` = **Tom Reid** (tomreidsemail@gmail.com) — a DIFFERENT user. The crew member `user_d002d8fab337` (chrissiekmann) is **NOT** in the crew array, consistent with a failed join.

### (4) Backend logs — POST /api/crew/join (last 24h)
- **7× 403 Forbidden**, 2× 200 OK. The repeated 403s match the email-mismatch rejection path.

## Root cause — which failure path is hit
The **403 email-mismatch** path, NOT expiry (invite is valid until 2026-11-04) and NOT 404.

The invite was addressed to `chris.siekmann.cs@googlemail.com` but the crew member registered/signed in as `chrissiekmann.cs@googlemail.com`. The local parts differ by a single dot:
- Invite:  `chris.siekmann.cs` (dot after "chris")
- User:    `chrissiekmann.cs`  (no dot)

The join check does an exact lowercased string comparison. Gmail/Googlemail treat dots in the local part as insignificant, so BOTH addresses deliver to the same inbox — the user received the email and clicked a valid link — but the app's exact-match comparison rejects with `403 "This invite was sent to chris.siekmann.cs@googlemail.com"`. Timeline also fits: invite created 08:14, user account created 08:25 under the dot-less spelling.

## Fixes
1. **User (owner Isabella)** — Re-send the crew invite to the EXACT address the crew member registered with: `chrissiekmann.cs@googlemail.com` (no dot between "chris" and "siekmann"). Re-inviting deletes the stale `chris.siekmann...` invite; the new link will then pass the email check. (Alternatively the crew member re-registers using the exact invited address, but correcting the invite is cleaner.)
2. **Code (E1, optional robustness)** — Normalize email before comparison in `join_crew`: for gmail.com/googlemail.com, strip dots from the local part and treat `googlemail.com` == `gmail.com`, so insignificant Gmail variations no longer cause a false 403. This prevents recurrence for any Gmail user.
